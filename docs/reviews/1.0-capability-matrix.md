# BASE-02 — 1.0 기능·검증 현황표

조사일: 2026-10-25 (Asia/Seoul). 기준: #41 병합 소스
`f8d13722b0d5622e60c8a3e0a663aefe9b47df7b`.
상위 계획은 [1.0 실행 로드맵](../roadmap-1.0.md)이다.

이 표는 **기준 소스**의 공개 계약·기본 UI·제품 예제·검증 범위를 구분한다.
로드맵에 적힌 기능이나 커스텀 렌더러로 이론상 구현 가능한 기능을 지원 완료로
계산하지 않는다. npm 게시 여부는 [릴리스 기록](https://github.com/Goatshave/open-grid/blob/f8d13722b0d5622e60c8a3e0a663aefe9b47df7b/docs/release.md)으로 별도 확인한다.

## 1. 판정과 증거 읽는 법

| 표시 | 의미 |
| --- | --- |
| S | 표에 명시한 범위의 공개 기능/렌더러가 있고 연결된 자동 검증이 있음. 1.0 전체 품질 완료를 뜻하지 않음 |
| P | 일부 계약/UX만 제공되거나 확인된 경계 조건·검증 공백이 있음 |
| E | 제품/예제에서 조합한 동작. 라이브러리 기본 제공 기능으로 계산하지 않음 |
| N | 해당 기능의 공개 계약과 유지보수되는 기본 UI를 확인하지 못함 |
| V | 검증이 부족해 판정 보류. 해당 환경에서 실패한다고 단정하는 의미는 아님 |

React/Vue/Svelte 열은 유지보수되는 UI/어댑터 기준이다. 코어 helper만 있는 경우
API가 있어도 UI 열은 E/P로 표시한다. 명시하지 않은 자동 브라우저 증거는
Chromium 기준이다. 세 엔진 전체 확인은 `B-I`로 연결한 다섯 통합 흐름에 한정한다.

### 기준 실행 증거

- **E-MAIN**: [병합 후 main CI][ci-main]의 Quality·UI Smoke·Required Gate 성공.
  타입, 공개 API, 하한 호환성, 단위 테스트, 예제/문서 빌드, 패키지 경계를 확인한다.
  UI Smoke는 기본/접근성 36개, HTTP 서버 45개, 세 엔진 통합 45개를 실행한다.
- **E-PR**: [#41 Release Verification][ci-release]의 전체 E2E 185개,
  세 엔진 통합 45개, artifact 소비와 bundle/DOM/heap/core/server 게이트 성공.
  실행 커밋은 `bc830fa`; 병합 커밋과 Git tree가
  `055b356234f4732bb48556dc65488c539654478c`로 같다. 커밋이 다른 수동 승인으로
  재사용하는 증거는 아니다.
- **E-LOCAL**: 이번 조사에서 코어를 다시 빌드하고 5개 identity/state 탐침을 실행했다.
  관찰값과 재현 명령은 5절에 있다. 이번 작업에서 전체 브라우저/성능 검사를
  새로 실행했다고 주장하지 않는다.
- **수동 증거**: 0.3 출시의 VoiceOver 확인은 과거 기록이다. 이 소스의 실제
  OS IME·클립보드·Safari·NVDA와 최종 수동 검토 완료 증거로 계산하지 않는다.

현황표를 채우기 위해 부분 구현을 완성 기능으로 승격하지 않는다.

## 5. 직접 확인한 ID/상태 경계

다음 관찰은 1.0 계약 우선순위를 정하는 근거다. 모든 행을 즉시 같은 방식으로
수정해야 한다는 뜻은 아니다. 특히 위치 ID와 선택 보존은 호환성/제품 정책을 먼저 정한다.

| 관찰 ID | 입력/동작 | 기준 소스의 실제 결과 | 분류·다음 대응 |
| --- | --- | --- | --- |
| ID-01 | 두 행의 `getRowId`가 같은 문자열 반환 | rows 2개, `rowsById` own key 1개, 마지막 행이 인덱스를 덮음 | 중복 ID 처리 계약·명시적 진단 없음 → `API-01-B` |
| ID-02 | 행 ID `__proto__` | own entry 없음, 해당 row가 인덱스 객체의 prototype이 됨 | 안전한 dictionary 저장/조회 회귀부터 보완 → `API-01-A` |
| ID-03 | 두 열이 같은 ID, accessor는 a/b | 열 2개이나 row의 ID 조회 값은 b의 값 `B` | 열 ID 유일성·오류 정책 → `API-01-B` |
| ID-04 | `getRowId` 없이 A/B 중 0 선택 후 데이터를 B/A로 교체 | 선택 0이 B를 가리킴 | 위치 fallback의 의미. 안정 ID 필요를 명시하며 기본 ID를 조용히 변경하지 않음 → `API-01-B/C` |
| STATE-01 | a 행에 focus/edit 후 `setOptions`로 data를 빈 배열로 교체 | 행 0개, focus/edit 좌표는 a를 유지 | 삭제와 서버 page-off의 구분 및 state reconciliation 계약 → `API-01-C` |

기본 재현(저장소 루트, `pnpm --filter @open-grid/core build` 후):

```sh
node --input-type=module <<'JS'
import { createGrid } from './packages/core/dist/index.js';
const columns = [{ accessorKey: 'id' }];
const duplicate = createGrid({ data: [{ id: 'x' }, { id: 'x' }], columns,
  getRowId: row => row.id }).getCoreRowModel();
console.log(duplicate.rows.length, Object.keys(duplicate.rowsById).length);
const special = createGrid({ data: [{ id: '__proto__' }], columns,
  getRowId: row => row.id }).getCoreRowModel().rowsById;
console.log(Object.hasOwn(special, '__proto__'), Object.getPrototypeOf(special)?.id);
JS
```

기준 결과는 `2 1`, `false __proto__`다. 이 문서는 과거 baseline을 기록한다.
수정 후에는 그 결과를 정상 동작의 기대값으로 테스트하지 않고, 안전한 새 계약에
대한 회귀를 추가한다. 상세 첫 작업은 [API-01 범위](1.0-api-01-scope.md)에 연결했다.
